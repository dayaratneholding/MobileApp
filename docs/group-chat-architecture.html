Text message

Sending a message

03

The phone shows the message immediately. SQL Server is the record. SignalR carries it to everyone in that group who is online.

1

Write it on the phone

The app creates an id and shows the bubble as sending. That same id is used if the send has to be retried.

2

Save one row

The chat API inserts the message in SQL Server. A repeated id returns the original row, so a weak network cannot duplicate it.

3

SignalR delivers it

Every member whose app is open in that group receives the message at once. The sender’s bubble becomes sent.

4

Update the group list

Other screens show the new preview and the unread count. A person can belong to any of the 15 groups.

An admin adds or removes people and renames the group. Any member can send. History loads in pages, newest first, from SQL Server.

Photos, voice, video, files

Sharing a file

04

The file itself never travels through SignalR. Storage holds the bytes. The message holds the link.

1

Ask for an upload

The phone tells the chat API the file name, type, and size. The API returns an upload destination.

2

Send the file to storage

The photo, voice note, video, or document goes to the file manager the app already uses.

3

Send the message

The chat row stores the type, size, duration, thumbnail, and link. SignalR broadcasts that row, the same way it broadcasts text.

4

Download when it is on screen

The other phone shows the bubble first, then fetches the file. Voice notes play from the audio file. Video uses a thumbnail until it opens.

Notifications

When the phone is told

05

SignalR is for people who have the app open. Expo Push is for everyone else. The server decides after the message is saved.

Where that person isWhat they getPush
App open on that group SignalR adds the message to the thread. No push
App open on another screen The group list and the unread badge update. No push
App closed or phone locked Expo Push sends the group name and a short preview, such as “Nimal: Photo”. The tap opens that group. Push
Group is muted The message is stored. The badge can update the next time the app opens. No push
Opening the thread marks it read. SQL Server stores the last message that person has seen, and the badge is the count of messages after that. Each phone registers its Expo push token at login and removes it at logout.

Database and deploy

SQL Server holds the record. Docker runs the API.

06

Four tables cover groups, membership, messages, and the phones that can receive a push. The live socket is not stored in the database.

Group
  • Id
  • Company id
  • Name and photo
  • Created by
Member
  • Group and user
  • Role: admin or member
  • Last read message
  • Muted until
Message
  • Id created on the phone
  • Group, sender, time
  • Type: text, image, audio, video, file
  • Text or file link, size, duration
Device
  • User
  • Platform
  • Expo push token
  • Removed on logout

Deploy

Put the chat API in one Docker container. Point it at a new database on your SQL Server, and at the file manager you already run. Leave the HCM and core APIs on their current hosts.

chat-api container SQL Server database Existing file manager

Sized for this rollout

About 200 people and 15 groups fit in that single container. A second copy of the API, and Redis in front of SignalR, wait until you run more than one container.
